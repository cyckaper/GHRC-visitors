# 操作流程：一場參訪從頭到尾

這份文件回答兩件事：**每一個步驟與按鈕是為了什麼**，以及**這個流程哪裡還不合理**。
規格看 `CLAUDE.md`，部署看 `DEPLOY.md`。

後台 `visit.healsdesign.org/admin.html`；最上面一個「這一場」是全站共用的選擇，五個分頁都在那一場上做事。

---

## 一、時間軸：一場參訪會經過什麼

| 什麼時候 | 誰 | 做什麼 | 在哪裡 |
|---|---|---|---|
| 收到來信 | 主辦端 | 貼信 → 抽資料 → 查背景 → 排流程 | 後台「訪前」 |
| 參訪前一兩天 | 主辦端 | 挑頁、產 .pptx、寄確認信 | 後台「簡報」＋「訪前」 |
| 當天 | 來賓 | 掃門口 QR → 看今日流程、五間老師卡片、留 email | 來賓專頁 |
| 來賓離開後 | 主持人 | 簽名簿、名片、三十秒口述、當天資料 | 後台「後續」 |
| 一兩天內 | 主辦端 | 草擬並寄出感謝信給名單上每一個人 | 後台「後續」動作五 |
| 一週內 | 來賓 | 回三個問題（可不具名） | 來賓專頁 `#respond` |
| 之後 | 主辦端 | 一頁摘要、跨場次彙整；資料自動備份到 Drive | 後台「資料」 |

**設計前提**：來賓只做兩件事——掃一次 QR、回三個問題。其他都在主辦端。

## 二、後台：每個步驟與按鈕的目的

### 中文與英文

兩邊都可以切，右上角那一顆鍵：

- **後台**：整個介面換成英文（分頁、說明、按鈕、提示、狀態，連母簡報的區塊名都換）。
  切下去會重新整理頁面——表單與還沒交出去的暫存本來就自己存著，不會掉東西。
  選擇記在這台裝置上，換一台要再按一次。**AI 寫出來的東西不翻**（抽取結果、信件草稿、摘要是資料，不是介面）。
- **來賓專頁**：本來就是兩種語言一起出現，這顆鍵只是換**哪一個當主語**——
  預設英文為主、中文為輔；按下去變成中文為主、英文為輔。韓國團、日本團的輔助語言仍然是韓文、日文。
  網址帶 `?ui=zh` 就直接是中文版（要寄中文版連結給人時用），`?ui=en` 反之。
  來賓在表單打到一半換語言，打的字會留著。

### 顏色在說什麼

顏色不是裝飾，是用來**分辨東西**的：

- **五間研究室各一色**（301 綠、302 藍、303 紫、304 琥珀、305 洋紅）——選頁的區塊、行程的每一列、
  來賓專頁的老師卡片與「想合作哪幾間」都是同一組顏色，換一個畫面也認得出是同一間。
  顏色寫在 `public/data/labs.json` 的 `color`，改那一個檔全站就跟著改。
- **六個分頁各一個顏色**：分頁按鈕、卡片標題左邊那一條、步驟號碼、主要按鈕都跟著走——
  一眼看得出人現在在哪一頁。頁面最上面那一條細線是五間的顏色（來賓專頁也有同一條）。
- **顏色不拿來講狀態**：做了沒做仍然是文字與綠勾（進度線那一排），
  螢幕只看得到灰階、或看不出某兩個顏色的差別，都不會少掉任何一項資訊。

### 最上面那一行

| 元件 | 目的 |
|---|---|
| 這一場（下拉） | 全站共用「現在在處理哪一場」。打開後台停在**今天或接下來最近**的那一場；沒有將來的場次就停在乾淨的「＋ 新的一場」——**過去的場次不會自己跳出來**（一打開就看到上禮拜那一場，會以為系統把舊東西留在畫面上）。要回頭處理舊的一場，這個下拉或最底下「以前做過的參訪」點一下就切過去 |
| ＋ 新的一場 | 明確表示「接下來要建新的」——填上單位名稱就自動建好 |
| 已存 14:32 | 自動存的回報。**沒有存檔按鈕**，改了欄位一秒多就存 |
| 不要這份草稿 | 只在「還沒存成一場」的草稿被帶回來時出現：清掉它，表單回空白 |
| 刪掉這一場 | 建錯就刪。已經有來賓回覆或已寄出感謝信的不給刪（那不是我們的東西）；Drive 備份不動 |
| 登入／登出 | 貼一次 ADMIN_TOKEN 換成這台裝置的憑證，半年不必再貼。共用電腦用完請登出 |

### 訪前

| 步驟／按鈕 | 目的 | 為什麼需要 |
|---|---|---|
| 1. 貼 email／上傳名單檔 → **AI 抽取** | 讀出單位、人名職稱、**隨行名單與 email**、日期時間、目的、興趣。信裡提的那一天就是日期（問句「10/5 有空嗎」也算）；**信裡沒有日期就留空**，日期底下說「填上日期就會自己存」——不會拿今天建一場 | 手打十幾個人的資料會漏，而漏掉的正好是訪後信寄不到的人 |
| 　（貼上的信會自己暫存） | 關掉網頁、手機切去接電話再回來，那封信還在 | 貼一封長信是十幾秒的事，掉一次就得回信箱重找一次 |
| 2. 確認訪客背景（欄位） | AI 讀的一律要人看過才算 | 抽錯不可怕，抽錯又沒人看才可怕 |
| 　**開始時間／結束時間** | 這一場**幾點到幾點** | 要決定的是這個，不是「總共幾分鐘」——長度由兩個時間算出來，寫在旁邊（「共 150 分」）。行程分配、後續提醒、行事曆 .ics 都跟著走。結束早於開始會當場說 |
| 　人數 | 年報與諮詢委員會的人次要用 | 排行程時沒那麼重要，不確定就先留著，之後再改 |
| 　網址代碼 | 來賓專頁網址的後半段 | 寄出信或有人回覆之前都還能改，之後固定（印出去的 QR 不能失效） |
| 　參訪名單 | 訪後信的收件人清單就是這一份 | 只留主要窗口，回饋就只剩一個人的意見。**刪掉一列會馬上存**，AI 查背景查的也一律是畫面上現在這一份 |
| 3. **AI 查訪客背景** | 查公開的專業資料，判斷**可能的參訪目的**、可能最想看哪幾間、可以先準備什麼 | 對方通常不會在信裡寫真正想要什麼；先判斷過，簡報與動線才挑得準 |
| 4. **通告研究室**（擬通告 → 複製到 LINE ／ 寄出 → 各室在支援人力表上填接待人員與共需幾分鐘 → 擬回報） | **查完背景就發、排行程之前**：告訴各研究室哪個單位什麼時候來、當天動線；最後一句「請各研究室回覆，該時段由哪位老師或人員接待」＋支援人力表的連結（點進去直接跳到這一場）。各室在表上填**接待人員與共需幾分鐘**，**填的分鐘自動排進下一步的今日流程**，也出現在來賓專頁的參訪流程；定案之後再回報一次。**座談的場次**（擬通告之前先勾「這場是座談」）五間都通告，只問老師能否出席 | 中心本來就是在 LINE 群組通知，但每次都要自己打、每次都漏掉一兩間。**先問再排**：各室要多少時間各室最清楚，填進來就排好，主辦端不必再抄一次（明確指示）。收件人只有**這一場會走到的那幾間**；訊息一律中文、條列、貼得進 LINE，**不署名、不寫回覆期限、不接龍**（明確指示：連結就是最後一行）。群組裡直接回的，填進設定分頁那張表，資料只有一份 |
| 　**這場是座談，不參觀研究室**（擬通告之前先勾） | 有些單位是來跟中心老師們座談、不用介紹各研究室：流程換成「總體介紹 → 座談」，**研究室參訪那一段的時間給座談、結束時間不變**（原本的綜合討論就是座談）；動線上只剩總體介紹 | 明確指示：「有一些單位參訪是跟老師們座談，不用介紹各研究室」；勾放在通告前面，各研究室才知道要怎麼參與（明確指示）。**通告照樣發給五間**，問的是「老師能否出席座談」；支援人力表上那一場每一間只有一個下拉選單「張俊彥 可參加／張俊彥 無法參加」（各研究室的老師是固定的，明確指示：「就不用再填寫表單了」；選項前面就是老師的名字），不填名字、不問分鐘；回報列出每一間可不可以參加；AI 挑頁不挑各研究室的頁；確認信寫「之後與中心老師座談」。取消勾就回到參觀（研究室之前填過的分鐘照填的排回去） |
| 5. **今日流程**（自動排好，看一眼就好） | 這一場幾點做什麼：一段一行，研究室參訪底下一間一行、各自的時段，每一間寫「研究室填」或「未填」、填了接待人員就寫出來 | **不必自己排**（明確指示：「5 行程應沒什麼作用了，可以簡化」）：各研究室在支援人力表上填的分鐘自動排進來，時間照著往後推，開始時間一改整排也跟著推。所以以前那顆「AI 排行程」拿掉了——它剩下的用處只有挑頁，搬到「簡報」分頁變成「AI 挑頁」。底下一行「流程排了 N 分」，跟「幾點到幾點」差多少直接講。同時是簡報第 2 頁與來賓專頁的內容來源，也決定一頁摘要裡「看了哪幾間各多久」 |
| 　要改再點開（**一張表**） | 例外才用：不去某一間（分鐘改成 0）、總體介紹換地點（預設 302）、加合照、改標題 | 平常收起來。「研究室參訪」那一列底下是每一間幾分鐘（研究室填的標「研究室填」），**分鐘一改，後面各段的時間就自己往後推**。以前還有一欄「頁碼」——那是簡報第 2 頁的欄位，產檔時照選了幾頁自己算，不再請人填。後台開著舊的那一份時研究室剛好填了，存檔也不會把它蓋回去，會說一聲「301 剛在支援人力表上填了分鐘，行程已經照著排好」 |
| 6. **確認信**（草擬 → 寄出） | 確認日期時間，把來賓專頁網址交出去 | **信裡就有專頁網址，所以寄出之後那個網址就固定了**。**預設只寄給名單上標「聯絡人」的那幾位**——日期還在往返時，把還沒定案的行程寄給全團只會造成困擾（名單上一個都沒標就先全選）。按鈕上直接寫「寄出確認信（N 位）」、旁邊列出名字。沒設定 Gmail 就給你 mailto 自己寄。署名預設對口老師。**寄出後又改了行程**，這裡會說「對方手上的時間是舊的」 |
| 來賓專頁 ＋ QR | 這一場專屬頁面的網址 | QR 印出來或投在簡報最後一頁，來賓自己掃，不必個別傳網址 |
| **以前做過的參訪**（最底下） | 列出最近幾場：類型、國家、人數、選了幾頁、有沒有摘要，同類單位標「同類」 | 排新的一場最想看的就是「同類單位上次怎麼排、選了哪幾頁」。點一列就切到那一場（手上這一場有暫存，不會掉）；全部歷次在「資料」分頁 |
| 複製網址 | 把來賓專頁網址複製起來 | 貼進信裡或 LINE 給對方 |
| 下載後續提醒 .ics | 把這一場加進行事曆，結束時間跳出來 | 系統本來就會在那個時間寄一封提醒信（見功能 4）；這顆是給想在行事曆上也看到的人 |

> 存檔後那一區**只留這兩顆**（都是對這一場的東西動手）。以前還有「選頁與產生簡報」「草擬確認信」「開後續頁」
> 三顆跳分頁的按鈕與一行「簡報：已選 N 頁」——上面的分頁列與進度線已經各做了一次同樣的事，第三份只是雜訊。
> 要去哪一頁看進度線那一排：綠勾是做過了，點一格就跳過去。

### 簡報

| 步驟／按鈕 | 目的 | 為什麼需要 |
|---|---|---|
| 這場不用簡報，只口頭介紹 | 整頁關掉選頁與產檔 | 有些參訪就是坐下來談，不需要投影片 |
| 選用頁次（**一個區塊一個勾**） | 決定這一場講哪幾區 | 母簡報 72 頁不可能全講，但也不必逐頁挑——要決定的是「這一場要不要講 302 規劃室」。勾了整區一起進去；裡面有哪幾頁點開來看。必選頁（封面、流程、架構、核心宣稱、謝謝）鎖住、永遠在。**勾完自己會存**，沒有存檔鍵。按了「全選」那一顆會變成實心的顏色、前面打 ✓，看得出選到了（全不選也一樣） |
| **AI 挑頁** | 依單位類型、來訪目的、興趣與今日流程上要去的那幾間挑區塊，也參考過去同類單位選過哪幾頁、哪幾頁被提問；旁邊寫一句為什麼這樣挑 | 以前是訪前「AI 排行程」順便挑的；行程交給研究室填之後，它就只剩挑頁這件事，所以搬到挑頁的地方。**只動選頁與第 1–3 頁的替換文字，今日流程不動**；動線上沒有的研究室不挑它的頁，座談的場次不挑任何一間研究室的頁 |
| 全選／全不選 | 快速起點 | |
| **產生簡報 .pptx** | 從母簡報挑出這幾頁、改寫第 1–3 頁、換第二語言、加 QR 頁，直接下載 | 母簡報是設計過的成品，只做子集化不重新生成，設計不會掉。**選到的影片頁，影片會留在檔案裡**（現場播得動；產檔報告會說留了幾支）——前提是當場選原始的母簡報，站台上那一份是瘦過的、沒有影片，那幾頁只剩海報。產出的簡報也會自動更正母簡報內文寫錯的「四間研究室／301-304」→ 五間、301-305。**照片不會被拉變形**：每一張圖都跟它的框比過，比例不對的**整張**照原比例放回框裡——母簡報裡被裁掉一截的也補回來，不會上下被截斷（明確指示；產檔報告會說更正了幾張）。**封面換成這一場**：單位、來賓（主賓排第一）、日期照這一場的紀錄寫，上一次的來賓不會留在封面上（產檔報告會列出封面寫了什麼）。**目錄頁只列這一份講到的章節**，沒講到的卡片拿掉、其餘往前補位。**母簡報的講稿不帶**（那是寫給上一次來賓的，寄出去對方也看得到） |
| 母簡報（上傳／移除） | 站台存一份母簡報，之後產檔不必每次選檔 | 一次性設定；含影片或太大的檔會先在瀏覽器裡瘦身 |

### 後續（來賓離開後五件事）

> **不必記得來**：參訪的結束時間一到，系統會寄一封提醒到中心信箱（還缺哪幾件、附一個直接打開這一頁的連結）。
>
> 這一頁的東西都是「做過就存在伺服器上」：拍過的簽名簿（原圖與讀出來的留言）、轉好的逐字稿與抽出來的欄位，
> 重新整理或換台機器打開都會自己載回來。還沒按「存入回饋」的手改內容則走暫存。

| 步驟／按鈕 | 目的 | 為什麼需要 |
|---|---|---|
| 動作一 **上傳並讀字**（簽名簿） | 實體本子拍一張存檔，AI 讀成留言 | 簽名簿是唯一不必請人動手的留話管道；原圖永久保留 |
| 動作二 **拍名片** → 加進這場的名單 | 現場拿到的名片變成名單上的人 | 隨行的人拿不到 email 時的正式備案——訪後信才寄得到他 |
| 動作三 **三十秒口述** → 抽取 → 存入回饋 | 主持人講：誰來、最想看哪一間、問了什麼、有無合作意願 | **受訪的是主持人自己**，不錄來賓（對部長級不禮貌，且被錄只會講官話） |
| 動作四 當天資料（PDF／合照／連結） | 放上來賓專頁 | 感謝信只能承諾頁面上真的有的東西，所以先放再寄信 |
| 動作五 **感謝信**（草擬 → 寄出） | 附上當天資料，並請他們回三個問題 | 前四件做完就在同一頁寄，不必再換分頁。收件人＝名單上每一個人 ＋ 當天在專頁留信箱的人（預設全勾）；按鈕上寫「寄出感謝信（N 位）」、旁邊列出名字。用中心的 Gmail 一封一封寄（沒設定就給 mailto）。署名預設中心主任 |
| 每張卡片右上角的 **本次沒有** | 這一場本來就不會有這件事 | **沒有簽名簿、沒交換名片、沒錄口述，參訪一樣走完了**，感謝信一樣該寄。標了就不算未完成：進度線顯示「本次沒有」，結束時的後續提醒也不再為它寄信。做到了以做到的為準 |

> 三個回應項目：想合作哪幾間（301–305 複選）、希望我們做什麼、**開放建議欄位**（請益語氣、一句話就好、可不具名）。
> 兩封信的畫面都會依參訪日期標出「現在該寄這一封」，寄過的就不再催。
| **來賓專頁的三個連結** | 同一個頁面三種用法，各寫一句什麼時候用 | 純網址＝訪前給、QR 用；`#email`＝當天留信箱；`#respond`＝訪後三個問題（放進感謝信） |

### 資料

> **一頁摘要不必按**：參訪過完、有來賓回覆之後，系統每天凌晨自己產一份；回覆陸續進來就自己重寫。
> 「AI 產一頁摘要」那顆是「現在就要」用的。

| 步驟／按鈕 | 目的 |
|---|---|
| **訪客來自哪裡**（世界地圖，最上面） | 一眼看出中心接待過哪些單位：**一個單位一個點，落在那個學校或公司所在的城市**（明確指示：點要能縮小到學校或公司，不要佔了整個國家）。位置是打開這一頁時系統自己用 AI 查的，查好地圖自己更新；查不到城市的先放在國家、畫成空心的圈。可以放大（上方＋／－／全圖、雙擊、兩指撐開），放大之後可以拖；有數字的是疊在一起的好幾個單位，點下去會放大，同一個城市放到最大還疊在一起的就直接列出來。點一個點列出那個單位的每一場，再點一列就跳到那一場的紀錄。**同一個單位只算一個**：中文名稱一樣、或英文名稱只差空白與標點（例如「Dun Yang」與「Dunyang」）就是同一個，首頁的地圖與來訪紀錄頁也一樣算。國名對不到的會列在圖下面（不會靜靜地漏掉），改那一場的「國家」欄位就會歸位 |
| 歷次參訪（點一列） | 看那一場的摘要與來賓回覆 |
| **公開頁上的說明**（點一列，那一場的紀錄裡） | 中心首頁的地圖與「來訪紀錄」頁（`/visits`）上這一場寫什麼：來訪人員、交流重點／成果（中英各一），或勾「這一場不公開」（地圖上也不畫）。匯入的舊紀錄已經帶了原表的字；系統裡排的一場預設是空的，公開頁只有日期、單位、國家、去了哪幾間——**來訪目的、名單不會自己跑出去**。打完自己存，重新整理就看得到 |
| **匯入以前的參訪**（歷次參訪右上角） | 系統上線之前的參訪（試算表、Word 或簡報檔）一次補進來，**兩張地圖（這一頁與中心首頁）、清單、年報數字就都有**（明確要求：「把所有參訪者加入中心首頁地圖，以及主辦端網頁資料地圖中」）。AI 把每一列讀成一筆：英文正式名稱、中文名稱、類型、國家；一列有好幾個單位（研討會的幾位講者來自不同學校）就拆開，**算同一場**，所以地圖上面那一行的「幾場」跟原表對得上。**讀完先列出來給人看，勾好才寫進去**；系統裡已經有的（同一天、同一個單位）勾不了，同一份再匯入一次也不會多出東西。原表沒寫的不補：人數沒寫就是「不知道」（那一行會說幾場不知道人數）、對口老師留空、不知道當天去了哪幾間。位置照舊自己去查。匯入的那幾場不進支援人力表（系統上線之前的，沒有人要填）；點一列看得到原表那一列寫了什麼。預覽底下預設勾著「**同時存成 Google 試算表**」：匯入完，名單變成 Drive「GHRC 參訪」資料夾裡的一份 Google 試算表（「GHRC 參訪名單」），**之後在那份試算表加一列，系統每十五分鐘看一次、自動加進來**（明確指示：「每一次有增加再自動加入」）——不必再按匯入 |
| **名單那一行**（歷次參訪底下，連上名單之後才有） | 連到哪一份 Google 試算表、上次什麼時候看的、上一次加了幾筆；「現在就看一次」不必等十五分鐘。打開「資料」分頁時也會看一次。名單裡**刪掉一列、改已經加進來的那一列**，系統裡那一場不會跟著刪或改（要改在這一頁改）；改了日期或單位就當成新的一列。系統的 Google 授權只看得到它自己建的檔案，所以看的是這一份，不是自己另外放在 Drive 上的 xlsx |
| **AI 產一頁摘要** | 把回覆、當天的動線安排、口述整理成一頁；同時記下哪幾頁被提問、被提到 |
| 立即備份到 Drive | 手動補救（平常自動備份，一場一個資料夾） |
| **AI 彙整**（跨場次） | 把歷次開放建議一起讀過，找出重複出現的問題 |
| 四個 CSV | 年報與諮詢委員會的原始數字 |

## 四、流程檢討

### 做對的地方（別「修」掉）

- **沒有存檔動作**、網址在用出去之前可以改、建錯就刪 —— 存檔是系統的帳，不是使用者的事
- **跑得久的 AI 一律走背景函式**，前端輪詢到底不叫人再按一次
- **開放建議可不具名，且後端不補回姓名** —— 這條管道能不能收到真話就靠這個
- **不做滿意度評分、不集章、不發問卷、不錄來賓** —— 每一條都有理由（見 CLAUDE.md 否決清單）
- **拍名片**補名單，讓「隨行的人拿不到 email」有正式解法
- **沒做完的東西自己暫存**（貼進來的信、打好的逐字稿、手改過還沒寄的信、還沒有單位名稱的表單）
- **該系統自己做的就不要叫人記得**：Drive 備份、一頁摘要、後續提醒都是自動的，按鈕只留給「現在就要」

### 還不合理的地方（依重要性）

**1. 閉環的最後一段沒接上** ✅ 已補（2026-09-13）
`slide_performance` 以前只寫不讀。現在 `netlify/lib/history.mts slideHistory()` 算出「每一頁過去選過幾次／同類單位選過幾次、哪幾頁被提問、哪幾頁被提到、來賓點名最想看哪幾間」，由 `plan-background` 交給提示詞；**選過哪幾頁直接讀每一場的 `visit.slides`**，所以不必等人按「一頁摘要」就有資料。提示詞明講「沒有數字不代表那頁不好」，避免變成排行榜。

**2. 缺一條「這一場到哪一步」的進度線** ✅ 已補（2026-09-13）
「這一場」那一張卡片下面一排：訪前（名單／背景研判／通告研究室（回了幾間）／簡報／確認信——今日流程是自動排的，不算一步）｜當天（簽名簿／名片／口述／當天資料）｜訪後（感謝信／回覆／一頁摘要）。綠勾＝做過、灰點＝還沒、`–`＝**本次沒有**（標過的那幾件），點一格跳到該做那件事的分頁。

已經交出去的東西**會不會過期**也在這一排講：行程改過之後，簡報那一格變成「簡報 需重產」、確認信那一格變成「確認信 行程已改」，綠勾收回來。網頁會跟著更新，但**已經寄出的信與下載的 .pptx 不會**——所以要說一聲，而不是繼續顯示做完了。

**3. 兩封信在兩個地方** ✅ 已改（2026-09-13）
兩封信各自回到它該在的時間點：**確認信在「訪前」**（排完行程、拿到專頁網址的下一步），**感謝信在「後續」動作五**（當天資料放上去之後就寄）。寄出走同一支端點只差 kind，畫面依日期標出「現在該寄這一封」；收件人清單兩邊各有一份（分開之後共用勾選只會讓人看不到自己勾了什麼）。確認信一樣可以從後台寄出並記下寄給誰——信裡有來賓專頁網址，所以寄出後那個網址就固定不再改。

**4. 一次性設定跟每場的事混在一起** ✅ 已改（2026-09-13）
多一個「設定」分頁：母簡報（從簡報分頁底部搬過來）、訪後信預設寄件者、外部服務狀態（只回「接好了沒」，不回金鑰）。老師卡片還不能在後台改，設定頁直接說明原因。

**5. 動線這條線在後台幾乎不存在** ⛔ 整套移除（2026-09-13，明確指示：暫時都不用）
曾經做過：後台自己產六個房間的 NFC 網址與電腦捷徑、`timeline` 表記下實際進出時間、沒有訊號的時段用行程推補。
現在全部拿掉——NFC 貼紙、簡報捷徑、來賓端的「我現在在哪一間」、動線表與 `timeline.csv`、`SIGNAL_KEY` 都不在了。
當天實際走到哪一間不再記錄；一頁摘要的「看了哪幾間」改用當天排定的動線。要找回來翻 git（移除前的最後一版 `191ee60`）。

**6. 一頁摘要沒有人會記得按** ✅ 已補（2026-09-13）
改成不必按：`summary-cron` 每晚台北時間**凌晨一點**掃一次，參訪過完、有回饋可寫的就自己產一份
（判斷在 `lib/visit.mjs needsSummary`）。來賓的回覆是好幾天之內陸續進來的，所以**比最新那筆回覆舊就重寫一次**；
不具名那一筆只有日期（真匿名的代價），一律當成那天的最後一刻——寧可多寫一次，也不要漏掉匿名建議。
排在 `drive-cron`（兩點）之前，當晚的備份就帶到新的摘要。「AI 產一頁摘要」那顆按鈕留著給「現在就要」用。

**7. 口述提醒只有 .ics，要人自己下載** ✅ 已補（2026-09-13）
管道選了**寄信**——中心已經有 Gmail 授權（訪後信在用），手機收信就會跳，不必再接第三個服務、不必裝 app。
`reminder-cron` 每十五分鐘看一次，參訪的**結束時間**（依今日流程，`visitEndAt`）一到就寄一封到中心信箱（四件事都做完、或都標了「本次沒有」就不寄）：
簽名簿、名片、口述、當天資料還缺哪幾件，附一個直接打開「後續」分頁的連結。一場只寄一次、四件事都做完了就不寄、
只看結束後六小時內的場次。收件信箱在「設定」分頁填（留空就用寄信那個帳號）。.ics 留著給想在行事曆上也看到的人。

**8. 「儲存選頁」按鈕留著會誤導** ✅ 已改（2026-09-13）
選頁跟訪前一樣自己存（勾完 1.2 秒後寫回），按鈕拿掉。全選／全不選／只選這區也會存。

**9. 來賓專頁三種連結沒在一個地方說清楚** ✅ 已改（2026-09-13）
「後續」開頭一張卡片把三個並列，各附一句什麼時候用：專頁網址（訪前給、門口 QR）、`#email`（當天留信箱）、`#respond`（訪後三個問題，放進感謝信）。

**10. 還沒交出去的東西一關網頁就沒了** ✅ 已補（2026-09-13）
後台大部分欄位都自己存，但幾個「最花時間打」的方框沒有：貼進來的 email、打好的逐字稿、手改過還沒寄出的信件、
還沒有單位名稱（算不出 visit_id、存不成一場）的整份表單。現在這些都暫存：**這台瀏覽器立刻一份、站台 `/api/draft` 一份**
（換台機器打開接得回來），取時間新的那一份。判斷什麼叫「還沒交出去」＝畫面上的值減去伺服器剛給的值，
所以 AI 草擬填進來、信寄出去、口述存入之後那一筆自然就空了。另外，**已經存在伺服器上卻沒載回畫面**的東西也補上了
（簽名簿的原圖與留言、口述的逐字稿與抽出來的欄位）——那些本來就沒掉，只是看起來像掉了。

**11. 待確認事項還開著**
訪後信預設寄件者（目前預設中心主任）、開放建議欄位措辭定稿、簽名簿形式、口述音檔保存期限、各老師的學經歷與照片。這些不是程式問題，但每一項都會影響來賓看到的東西。

**12. Google 的授權過期了，兩週沒人知道** ✅ 已補（2026-10-01）
Drive 備份、參訪名單的 Google 試算表、從後台寄信共用一組 Google 授權。環境變數裡那一份是同意畫面還在「測試」時拿的，七天就失效——
Drive 備份從九月中默默停了，匯入名單時才看到一行 `invalid_grant`。以前要重新授權得去 OAuth Playground 拿一組、貼進 Netlify、重新部署。
現在：設定分頁**「連上 Google」**一顆鍵（用中心的帳號允許一次，授權存在站台上）；設定分頁那一行真的換一次 token 才寫「已連上」，
