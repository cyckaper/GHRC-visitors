# 操作流程：一場參訪從頭到尾

這份文件回答兩件事：**每一個步驟與按鈕是為了什麼**，以及**這個流程哪裡還不合理**。
規格看 `CLAUDE.md`，部署看 `DEPLOY.md`。

後台 `visit.healsdesign.org/admin.html`；最上面一個「這一場」是全站共用的選擇，五個分頁都在那一場上做事。

---

## 一、時間軸：一場參訪會經過什麼

| 什麼時候 | 誰 | 做什麼 | 在哪裡 |
|---|---|---|---|
| 收到來信 | 主辦端 | 貼信 → 抽資料 → 查背景 → 排流程 | 後台「訪前」 |
| 參訪前一兩天 | 主辦端 | 挑頁、產 .pptx、寄確認信 | 後台「簡報」＋「信件」 |
| 當天 | 來賓 | 掃門口 QR → 看今日流程、五間老師卡片、留 email | 來賓專頁 |
| 當天 | 老師／主持人 | 開簡報（捷徑送出動線訊號） | 研究室電腦 |
| 來賓離開後 | 主持人 | 簽名簿、名片、三十秒口述、當天資料 | 後台「收工」 |
| 一兩天內 | 主辦端 | 草擬並寄出感謝信給名單上每一個人 | 後台「信件」 |
| 一週內 | 來賓 | 回三個問題（可不具名） | 來賓專頁 `#respond` |
| 之後 | 主辦端 | 一頁摘要、跨場次彙整；資料自動備份到 Drive | 後台「資料」 |

**設計前提**：來賓只做兩件事——掃一次 QR、回三個問題。其他都在主辦端。

## 二、後台：每個步驟與按鈕的目的

### 顏色在說什麼

顏色不是裝飾，是用來**分辨東西**的：

- **五間研究室各一色**（301 綠、302 藍、303 紫、304 琥珀、305 洋紅）——選頁的區塊、行程的每一列、
  動線表的房號、來賓專頁的老師卡片與「想合作哪幾間」都是同一組顏色，換一個畫面也認得出是同一間。
  顏色寫在 `public/data/labs.json` 的 `color`，改那一個檔全站就跟著改。
- **六個分頁各一個顏色**：分頁按鈕、卡片標題左邊那一條、步驟號碼、主要按鈕都跟著走——
  一眼看得出人現在在哪一頁。頁面最上面那一條細線是五間的顏色（來賓專頁也有同一條）。
- **顏色不拿來講狀態**：做了沒做仍然是文字與綠勾（進度線那一排），
  螢幕只看得到灰階、或看不出某兩個顏色的差別，都不會少掉任何一項資訊。

### 最上面那一行

| 元件 | 目的 |
|---|---|
| 這一場（下拉） | 全站共用「現在在處理哪一場」。打開後台停在**今天或接下來最近**的那一場；沒有將來的場次就停在乾淨的「＋ 新的一場」——**過去的場次不會自己跳出來**（一打開就看到上禮拜那一場，會以為系統把舊東西留在畫面上）。要回頭處理舊的一場，這個下拉或最底下「以前做過的參訪」點一下就切過去 |
| ＋ 新的一場 | 明確表示「接下來要建新的」——填上單位名稱就自動建好 |
| 已存 14:32 | 自動存的回報。**沒有存檔按鈕**，改了欄位一秒多就存 |
| 不要這份草稿 | 只在「還沒存成一場」的草稿被帶回來時出現：清掉它，表單回空白 |
| 刪掉這一場 | 建錯就刪。已經有來賓回覆或已寄出感謝信的不給刪（那不是我們的東西）；Drive 備份不動 |
| 登入／登出 | 貼一次 ADMIN_TOKEN 換成這台裝置的憑證，半年不必再貼。共用電腦用完請登出 |

### 訪前

| 步驟／按鈕 | 目的 | 為什麼需要 |
|---|---|---|
| 1. 貼 email／上傳名單檔 → **AI 抽取** | 讀出單位、人名職稱、**隨行名單與 email**、日期時間、目的、興趣 | 手打十幾個人的資料會漏，而漏掉的正好是訪後信寄不到的人 |
| 　（貼上的信會自己暫存） | 關掉網頁、手機切去接電話再回來，那封信還在 | 貼一封長信是十幾秒的事，掉一次就得回信箱重找一次 |
| 2. 確認訪客背景（欄位） | AI 讀的一律要人看過才算 | 抽錯不可怕，抽錯又沒人看才可怕 |
| 　網址代碼 | 來賓專頁網址的後半段 | 寄出信或有人回覆之前都還能改，之後固定（印出去的 QR 不能失效） |
| 　參訪名單 | 訪後信的收件人清單就是這一份 | 只留主要窗口，回饋就只剩一個人的意見。**刪掉一列會馬上存**，AI 查背景查的也一律是畫面上現在這一份 |
| 3. **AI 查訪客背景** | 查公開的專業資料，判斷**可能的參訪目的**、可能最想看哪幾間、可以先準備什麼 | 對方通常不會在信裡寫真正想要什麼；先判斷過，簡報與動線才挑得準 |
| 4. **AI 排行程** | 排出今日流程（印在簡報第 2 頁）與現場動線 | 時間分配是每場都要重做的算術，交給程式。它也會順便先挑好簡報頁次，但那件事的家在「簡報」分頁，所以按鈕不寫「與選頁」——排完才在旁邊說一句「也挑了 N 頁」 |
| 　今日流程 | 對來賓公告的時間表 | 同時是簡報第 2 頁與來賓專頁的內容來源 |
| 　現場動線 | 來賓幾點走到哪一間（留 0 表示不去） | 也是動線紀錄的底稿：沒有訊號的時段用它推補 |
| 來賓專頁 ＋ QR | 這一場專屬頁面的網址 | QR 印出來或投在簡報最後一頁，來賓自己掃，不必個別傳網址 |
| **以前做過的參訪**（最底下） | 列出最近幾場：類型、國家、人數、選了幾頁、有沒有摘要，同類單位標「同類」 | 排新的一場最想看的就是「同類單位上次怎麼排、選了哪幾頁」。點一列就切到那一場（手上這一場有暫存，不會掉）；全部歷次在「資料」分頁 |
| 複製網址 | 把來賓專頁網址複製起來 | 貼進信裡或 LINE 給對方 |
| 下載收工提醒 .ics | 把這一場加進行事曆，結束時間跳出來 | 系統本來就會在那個時間寄一封提醒信（見功能 4）；這顆是給想在行事曆上也看到的人 |

> 存檔後那一區**只留這兩顆**（都是對這一場的東西動手）。以前還有「選頁與產生簡報」「草擬確認信」「開收工頁」
> 三顆跳分頁的按鈕與一行「簡報：已選 N 頁」——上面的分頁列與進度線已經各做了一次同樣的事，第三份只是雜訊。
> 要去哪一頁看進度線那一排：綠勾是做過了，點一格就跳過去。

### 簡報

| 步驟／按鈕 | 目的 | 為什麼需要 |
|---|---|---|
| 這場不用簡報，只口頭介紹 | 整頁關掉選頁與產檔 | 有些參訪就是坐下來談，不需要投影片 |
| 選用頁次（**一個區塊一個勾**） | 決定這一場講哪幾區 | 母簡報 72 頁不可能全講，但也不必逐頁挑——要決定的是「這一場要不要講 302 規劃室」。勾了整區一起進去；裡面有哪幾頁點開來看。必選頁（封面、流程、架構、核心宣稱、謝謝）鎖住、永遠在。**勾完自己會存**，沒有存檔鍵 |
| 全選／全不選 | 快速起點 | |
| **產生簡報 .pptx** | 從母簡報挑出這幾頁、改寫第 1–3 頁、換第二語言、加 QR 頁，直接下載 | 母簡報是設計過的成品，只做子集化不重新生成，設計不會掉 |
| 母簡報（上傳／移除） | 站台存一份母簡報，之後產檔不必每次選檔 | 一次性設定；含影片或太大的檔會先在瀏覽器裡瘦身 |

### 收工（來賓離開後四件事）

> **不必記得來**：參訪的結束時間一到，系統會寄一封提醒到中心信箱（還缺哪幾件、附一個直接打開這一頁的連結）。
>
> 這一頁的東西都是「做過就存在伺服器上」：拍過的簽名簿（原圖與讀出來的留言）、轉好的逐字稿與抽出來的欄位，
> 重新整理或換台機器打開都會自己載回來。還沒按「存入回饋」的手改內容則走暫存。

| 步驟／按鈕 | 目的 | 為什麼需要 |
|---|---|---|
| 動作一 **上傳並讀字**（簽名簿） | 實體本子拍一張存檔，AI 讀成留言 | 簽名簿是唯一不必請人動手的留話管道；原圖永久保留 |
| 動作二 **拍名片** → 加進這場的名單 | 現場拿到的名片變成名單上的人 | 隨行的人拿不到 email 時的正式備案——訪後信才寄得到他 |
| 動作三 **三十秒口述** → 抽取 → 存入回饋 | 主持人講：誰來、最想看哪一間、問了什麼、有無合作意願 | **受訪的是主持人自己**，不錄來賓（對部長級不禮貌，且被錄只會講官話） |
| 動作四 當天資料（PDF／合照／連結） | 放上來賓專頁 | 感謝信只能承諾頁面上真的有的東西，所以先放再寄信 |
| **來賓專頁的三個連結** | 同一個頁面三種用法，各寫一句什麼時候用 | 純網址＝訪前給、QR 用；`#email`＝當天留信箱；`#respond`＝訪後三個問題（放進感謝信） |

### 信件（兩封信都在這裡）

| 步驟／按鈕 | 目的 |
|---|---|
| 收件人 | 名單上每一個人 ＋ 當天在專頁留信箱的人；**兩封信共用這一份勾選** |
| **AI 草擬確認信** →（參訪前寄） | 確認日期時間、把來賓專頁網址交出去 |
| **寄出確認信** | 信裡有專頁網址，**寄出之後那個網址就固定了** |
| **AI 草擬感謝信** →（參訪後寄） | 附上當天資料、放進三個回應項目的連結 |
| **寄出感謝信** | 用中心的 Gmail 一封一封寄（沒設定 Gmail 就給 mailto 自己寄） |
| 寄件者（各自可選） | 確認信預設對口老師、感謝信預設中心主任 |

畫面會依參訪日期標出「現在該寄這一封」，寄過的就不再催。

> 三個回應項目：想合作哪幾間（301–305 複選）、希望我們做什麼、**開放建議欄位**（請益語氣、一句話就好、可不具名）。

### 資料

> **一頁摘要不必按**：參訪過完、有來賓回覆之後，系統每天凌晨自己產一份；回覆陸續進來就自己重寫。
> 「AI 產一頁摘要」那顆是「現在就要」用的。

| 步驟／按鈕 | 目的 |
|---|---|
| **訪客來自哪裡**（世界地圖，最上面） | 一眼看出中心接待過哪些國家：一個國家一個點，點的大小是場次。點一下列出那個國家的每一場，再點一列就跳到那一場的紀錄。國名對不到的會列在圖下面（不會靜靜地漏掉），改那一場的「國家」欄位就會歸位 |
| 歷次參訪（點一列） | 看那一場的摘要、來賓回覆、現場動線 |
| **AI 產一頁摘要** | 把回覆、動線、口述整理成一頁；同時記下哪幾頁被提問、被提到 |
| 立即備份到 Drive | 手動補救（平常自動備份，一場一個資料夾） |
| **AI 彙整**（跨場次） | 把歷次開放建議一起讀過，找出重複出現的問題 |
| 四個 CSV | 年報與諮詢委員會的原始數字 |

### 設定（一次做完就不用再碰）

> 這裡多了一格「收工提醒寄到」：參訪結束時那封提醒信寄到哪個信箱（留空就用寄信那個帳號）。

| 區塊 | 目的 |
|---|---|
| 母簡報 | 站台存一份，之後每場產簡報不必再選檔（可直接選原始母簡報，瀏覽器會先瘦身） |
| 現場動線 | 六個房間的 NFC 網址、Windows／Mac 捷徑檔、可印的 QR；iPhone 貼紙的設定步驟也在那裡 |
| 預設值 | 訪後信預設寄件者（個別那一場還是可以在「信件」改） |
| 外部服務 | Claude／Whisper／Gmail／Drive／SIGNAL_KEY／母簡報**接好了沒**——只看得到有無，看不到金鑰 |
| 老師卡片 | 目前在 repo 的 `labs.json`，還不能在後台改（待確認 1） |

## 三、來賓端（`/<visit_id>`）

同一個網址，依日期換樣子：

| 階段 | 看到什麼 | 為什麼 |
|---|---|---|
| 訪前 | 「將參訪」、今日流程、五間老師卡片 | 先知道會看到什麼、誰負責 |
| 當天 | ＋ 留 email、備援按鍵 | 現場才需要；留信箱是為了訪後寄得到他 |
| 訪後 | 「感謝蒞臨」、當天資料、**三個回應項目** | 從感謝信按進來就直接看到要回的問題 |

全頁英文為主、第二語言為輔（預設中文，韓／日團改韓／日文）。

## 四、流程檢討

### 做對的地方（別「修」掉）

- **沒有存檔動作**、網址在用出去之前可以改、建錯就刪 —— 存檔是系統的帳，不是使用者的事
- **跑得久的 AI 一律走背景函式**，前端輪詢到底不叫人再按一次
- **開放建議可不具名，且後端不補回姓名** —— 這條管道能不能收到真話就靠這個
- **不做滿意度評分、不集章、不發問卷、不錄來賓** —— 每一條都有理由（見 CLAUDE.md 否決清單）
- **拍名片**補名單，讓「隨行的人拿不到 email」有正式解法
- **沒做完的東西自己暫存**（貼進來的信、打好的逐字稿、手改過還沒寄的信、還沒有單位名稱的表單）
- **該系統自己做的就不要叫人記得**：Drive 備份、一頁摘要、收工提醒都是自動的，按鈕只留給「現在就要」

### 還不合理的地方（依重要性）

**1. 閉環的最後一段沒接上** ✅ 已補（2026-09-13）
`slide_performance` 以前只寫不讀。現在 `netlify/lib/history.mts slideHistory()` 算出「每一頁過去選過幾次／同類單位選過幾次、哪幾頁被提問、哪幾頁被提到、來賓點名最想看哪幾間」，由 `plan-background` 交給提示詞；**選過哪幾頁直接讀每一場的 `visit.slides`**，所以不必等人按「一頁摘要」就有資料。提示詞明講「沒有數字不代表那頁不好」，避免變成排行榜。

**2. 缺一條「這一場到哪一步」的進度線** ✅ 已補（2026-09-13）
「這一場」那一張卡片下面一排：訪前（名單／背景研判／今日流程／簡報／確認信）｜當天（簽名簿／名片／口述／當天資料）｜訪後（感謝信／回覆／一頁摘要）。綠勾＝做過、灰點＝還沒，點一格跳到該做那件事的分頁。

**3. 兩封信在兩個地方** ✅ 已改（2026-09-13）
分頁改名「信件」，兩封信都在那裡，**收件人共用一份勾選**，寄出走同一支端點只差 kind，畫面依日期標出「現在該寄這一封」。順手補上一個一直缺的東西：**確認信以前只能草擬、不能從後台寄出**；現在可以，而且會記下寄給誰——信裡有來賓專頁網址，所以寄出後那個網址就固定不再改。

**4. 一次性設定跟每場的事混在一起** ✅ 已改（2026-09-13）
多一個「設定」分頁：母簡報（從簡報分頁底部搬過來）、現場動線捷徑與 NFC（從資料分頁搬過來）、訪後信預設寄件者、外部服務狀態（只回「接好了沒」，不回金鑰）。老師卡片還不能在後台改，設定頁直接說明原因。

**5. 動線這條線在後台幾乎不存在** ✅ 已補（2026-09-13）
「資料」分頁多一區「現場動線設定」：六個房間（總體介紹＋301–305）各給 NFC 網址、Windows `.bat`、macOS `.command`、可印的 QR，另附 iPhone 貼紙的設定步驟。`scripts/make-shortcuts.mjs` 留著給批次產檔用。沒設 `SIGNAL_KEY` 時會直接說「這些網址送不出訊號」。

**6. 一頁摘要沒有人會記得按** ✅ 已補（2026-09-13）
改成不必按：`summary-cron` 每晚台北時間**凌晨一點**掃一次，參訪過完、有回饋可寫的就自己產一份
（判斷在 `lib/visit.mjs needsSummary`）。來賓的回覆是好幾天之內陸續進來的，所以**比最新那筆回覆舊就重寫一次**；
不具名那一筆只有日期（真匿名的代價），一律當成那天的最後一刻——寧可多寫一次，也不要漏掉匿名建議。
排在 `drive-cron`（兩點）之前，當晚的備份就帶到新的摘要。「AI 產一頁摘要」那顆按鈕留著給「現在就要」用。

**7. 口述提醒只有 .ics，要人自己下載** ✅ 已補（2026-09-13）
管道選了**寄信**——中心已經有 Gmail 授權（訪後信在用），手機收信就會跳，不必再接第三個服務、不必裝 app。
